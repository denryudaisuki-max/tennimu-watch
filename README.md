# 空席・空室監視 → LINE通知

GitHub Actions で5分ごとにチェックし、狙っているものが取れる状態になったら LINE に通知します。
PC は閉じていて構いません。

監視しているものは2つです。

| # | 対象 | 条件 |
|---|---|---|
| 1 | **テニミュのチケット** | 2026/8/30(日) 17:30開演　TACHIKAWA STAGE GARDEN |
| 2 | **東横インの空室** | 仙台エリア 4館　2026/10/03〜10/04　1名1室 |

どちらも「取れない → 取れる」に変わった瞬間だけ通知します。同じ状態が続く間は再通知しません。

## 1. チケット監視（`check.py`）

イープラスの [公演詳細ページ](https://eplus.jp/sf/detail/0473460001) の HTML を読みます。

このページの受付ステータスは、席種（全席指定 / サイドシート / 見切席）の
**どれか1つでも空きがあれば「受付中」** になります。保存済みの申込画面と突き合わせて確認済みです。

| 公演 | 申込画面の席種 | 詳細ページの表示 |
|---|---|---|
| 8/30 12:00 | × × △ | 受付中 |
| **8/30 17:30** | **× × ×** | **予定枚数終了** |

「予定枚数終了」→「受付中」で発火します。

## 2. 東横イン監視（`check_hotel.py`）

HTML ではなく、予約サイトが内部で使っている **tRPC の JSON API** を直接叩きます。
認証不要で、ホテルごとに空室有無と最安値が返るため、HTMLパースより安定しています。

```
GET https://www.toyoko-inn.com/api/trpc/hotels.availabilities.prices
→ {"00011": {"lowestPrice": 8700, "existEnoughVacantRooms": true, "isUnderMaintenance": false}, ...}
```

監視対象は仙台の4館です。

| コード | ホテル |
|---|---|
| 00011 | 東横INN仙台東口1号館 |
| 00024 | 東横INN仙台東口2号館 |
| 00036 | 東横INN仙台西口広瀬通 |
| 00058 | 東横INN仙台駅西口中央 |

`existEnoughVacantRooms` が `false → true` になったホテルだけを、価格と予約リンク付きで通知します。
メンテナンス中（`isUnderMaintenance`）は満室扱いです。

## 条件を変えるには

### チケット

`check.py` の `TARGET_KEY` を書き換えます。キーは詳細ページの
`<article class="block-ticket-article {キー} local-...">` から取れます。

```
20260830-開演-1730-13
└ 日付   └開演 └時刻 └都道府県コード(13=東京)
```

### ホテル

`check_hotel.py` の先頭の定数を書き換えます。

```python
AREA_ID = 439          # 検索URLの area= の値
AREA_LABEL = "仙台"
CHECKIN = "2026-10-03" # 泊まる日（JST）
NIGHTS = 1
PEOPLE = 1
ROOMS = 1
HOTELS = {"00011": "東横INN仙台東口1号館", ...}   # コードは検索URLの /detail/xxxxx/ から
```

ホテルのコードとエリアIDは、東横インのサイトで検索したときのURLから読み取れます。

## セットアップ（設定済み）

- リポジトリは **Public**。5分間隔だと月およそ8,600分になり、プライベートの無料枠（月2,000分）では
  1週間で尽きます。パブリックなら Actions は無制限・無料です
- LINE のトークンは `LINE_CHANNEL_ACCESS_TOKEN` という名前の Secret に登録済み
- Bot を LINE で友だち追加済み（これがないと送信は成功扱いでも届きません）

## 動作確認

**Actions タブ → 「チケット監視」→ Run workflow** で手動実行できます。

通知そのものを試したいときは、対象を一時的に「取れる」条件に変えて実行すると LINE が飛びます
（チケットなら `TARGET_KEY` を `20260830-開演-1200-13`、ホテルなら `CHECKIN` を空室のある日付に）。
確認後は必ず戻してください。

## 注意点

- **スケジュールは遅れます。** GitHub Actions の cron は最短5分ですが、混雑時は数分〜十数分ずれます。
  瞬間的に出て消える戻り席・戻り部屋は取りこぼす可能性があります
- **リポジトリが60日間無活動だとスケジュールが自動停止します。** 状態変化時は自動コミットされるので、
  通常は問題になりません
- LINE の無料枠はコミュニケーションプランで**月200通**。超過しても課金はされず、送信できなくなるだけです。
  5分ごとのチェック自体は1通も消費しません
- どちらかの監視でデータを取得できない状態が3回続くと、警告を LINE に送り、ジョブも失敗させます
  （GitHub から障害メールが届きます）。片方が失敗しても、もう片方は動きます

## ファイル

| ファイル | 役割 |
|---|---|
| `common.py` | LINE送信・HTTP取得・状態の読み書き（共通） |
| `check.py` | チケット監視 |
| `check_hotel.py` | 東横イン監視 |
| `state.json` / `state_hotel.json` | 前回の状態（連投防止用・自動更新） |
| `.github/workflows/watch.yml` | 5分ごとの実行 |

## 終わったら

不要になったらリポジトリを削除するか、Actions タブでワークフローを Disable してください。
